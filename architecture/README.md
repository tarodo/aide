# Architecture Knowledge Base

## 1. Goals

The purpose of this directory is to serve as a comprehensive and easy-to-navigate knowledge base for the system's architecture. It is intended for both new and existing team members (developers, QAs, etc.) to quickly understand the system's structure, key architectural decisions, and common technical processes.

The main goals are:

*   **Provide a single point of entry:** Simplify navigation and information discovery.

*   **Structure information:** Organize documents by their purpose (overviews, decisions, guides).

*   **Enhance team productivity:** Offer practical guides and high-level diagrams for rapid project onboarding.

## 2. Structure Overview

This directory is organized into three main sections:

*   **[C4 Model](./c4-model/):** Visual diagrams that describe the system's architecture at different levels of abstraction. This is the best place to start for a high-level overview.

*   **[Architectural Decision Records (ADRs)](./adr/):** A log of significant architectural decisions. Each ADR answers the question, "Why did we make this choice?"

*   **[Guides](./guides/):** Practical, "how-to" documents for developers. These are living documents that should be kept up-to-date.
